Named sections, paired fields, an explicit verdict and a footer that names the sources. Long results page on section boundaries, so a record never splits across pages.

Layout

Sections, not soup

Every command returns named blocks — geography, network, anonymity, reverse DNS — with the header repeated on each page.

Anonymity

VPN, proxy, Tor

Address checks merge two independent risk models, label the provider and score exposure. Cloud ranges are reported as hosting, not as evasion.

Provenance

Sources on every page

The footer names the registry, resolver or index behind each value, and locally computed results say so.

02 — Coverage

Six kinds of question.

Public data only. No breach dumps, no private accounts, no credential testing — and no automation of anything that needs a human decision.

01 / Invites and handles

Vanity, invites and handles

Resolve invite links and bare codes, read server metadata, then watch up to eight codes on an interval. Handles are checked across seven platforms with a score and three usable alternates.

vanitycheckvanitywatchvanitysnipeusernamecheckusernamesnipe
02 / Network

Network and domain

DNS, certificate transparency, headers, redirect chains and ASN context, normalised into blocks instead of raw tool output.

03 / Web

Web and identity pivots

Metadata, robots, sitemaps, technology hints and social pivots, each with a confidence note and the next thing worth checking.

04 / Craft

Payload craft

Forty craft commands for marking documents, decoding transport layers and building test payloads for defensive work.

05 / Vuln

Vulnerability context

CVEs with EPSS, KEV status, CWE context and severity maths, plus URL and file reputation where a key is configured.

06 / Limits

Rate limits, not guesswork

Per-user ceilings, watch slots, cache windows and audit rows are configured in one place and enforced on every entry point.

05 — Deploy

Three steps, no build system.

The site is static and the bot is plain Python. Environment variables, limits, optional keys and the policy live in the docs.

01

Install

Create a virtual environment, install the requirements and copy the sample environment file.

python -m venv .venv
pip install -r requirements.txt
02

Configure

Set the token and owner IDs, then tune the gate in the access console and apply the generated line.

.accesskey rotate
.accessimport <export>
03

Sync and run

Start the bot, run .sync once so Discord has the current tree, then approve the operators.

python bot.py
.sync · .approve <user id>
