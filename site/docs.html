Operating notes.

Deploy

Python 3.11 or newer. The bot uses discord.py 2.5+ for container rendering, plus aiohttp, python-dotenv, phonenumbers and headless OpenCV.

python -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate
pip install -r requirements.txt
cp .env.example .env             # then fill in the token
python bot.py

The minimum environment is two values. Everything else has a default.

VariableDefaultMeaning
DISCORD_TOKEN—Bot token. Required.
OWNER_IDS—Comma-separated IDs. Required; these bypass approval and maintenance.
COMMAND_PREFIX.Prefix for text commands. The access console can narrow it further, not widen it beyond five characters.
GUILD_IDunsetGuild whose stale slash-command copies are cleared on sync. Commands are registered once, globally; a guild copy makes them appear twice.

LOG_CHANNEL_IDunsetFallback audit channel when the stored config does not name one.

MAINTENANCEfalseCold-start maintenance flag; the live value lives in the store.
CACHE_TTL300Seconds a network result stays warm.
MAX_CONCURRENCY4Outbound request ceiling.

Slash surface

Ten category wrappers — /net, /domain, /web, /identity, /social, /discord, /vuln, /crypto, /craft, /tools — take an autocompleted command name and the arguments you would type after the prefix. /vpncheck address: and /ip address: are direct commands, and owner-only /sync re-registers the tree and reports exactly what Discord accepted.

The tree is registered once, globally, and covers servers and bot DMs. Guild-scoped copies left by older builds are deleted on the next sync, because Discord lists global and guild registrations side by side. Group DMs and other private channels require the app's User Install context: enable it in the Developer Portal and set USER_INSTALL=true. A sync that is rejected for an unsupported context now names the failing scope and Discord's reason instead of failing silently.

Serve the siteStatic files, no build step: python -m http.server 8000 --directory site, then open http://localhost:8000. The pages load only their own assets. There is no analytics call, no external font and no telemetry.

Commands & catalogue

Commands are registered by cogs, and most of the arsenal lives in a table rather than as decorated functions. That would normally let the website drift, so tools/build_catalog.py parses the source without importing it and writes site/assets/commands.js.

python tools/build_catalog.py
# 380 commands · 626 callable names · 246 aliases

The generator reads @intel and @commands.command decorators, the gen subcommands and the _TOOLS / _ARSENAL registries. Re-run it after adding or renaming anything; if a command is missing from the index, it is missing from the bot.

Report layout

Every lookup renders through core/v2.py. Four rules hold for all of them:

  • Sections are atomic. Pagination splits on section boundaries, never inside a section, so a page always ends with a complete record.
  • Headers repeat. Each page carries the command, target and summary strip so a screenshot keeps its context.
  • Budgets are fixed. At most 16 fields or 7,200 characters per page, with inline pairing for short values.
  • Provenance is explicit. The footer lists sources, and locally computed results say so.

Past nine sections a result gets an index field, and the paginator adds a section jump menu. The numeric buttons stay for small results.

Access control

Every entry point runs the same check: the prefix command guard and the slash tree guard both call evaluate_access. Order of evaluation:

  1. Is the caller an owner? Owners bypass approval and maintenance.
  2. Is maintenance on? Refuse with the configured maintenance note.
  3. Is approval required and the caller absent from the allow-list? Refuse with the denied note.
  4. Is this a DM while DMs are disabled? Refuse.
  5. Then the command's own checks run: usage, ownership and network access.

The configuration lives in one JSON document in the key/value table. core/access.py normalises it, mirrors the maintenance flag and the watch interval to the keys other modules already read, and keeps a three-second cache so the hot path stays cheap.

Apply a configUse the access console to generate the line, then .accessimport <export> in Discord. .accessexport produces the same block from the live bot; .accessfields lists what is settable.

Watchtower

The snipers accept a bare code, a path or a full invite link, including the ?event= form. Resolution unwraps base64-ish candidates and caches results for 30 seconds so a batch check does not hammer the invite endpoint.

CommandPurpose
.vanitycheckOne invite: state, server, members, features, risk.
.vanitysnipeAvailability plus a claim checklist; never automates the claim itself.
.vanitywatchBatch watch, up to the configured ceiling, one event per transition.
.usernamecheckOne handle across seven platforms, with a score line.
.usernamesnipeRelease plan and fallbacks; no automation.

Polling interval is read from the stored config on every watch start, so changing it in the console applies to the next watch rather than requiring a restart. The floor is 30 seconds; 45 or more is recommended.

Anonymity checks

Every address report carries a VPN / proxy / Tor verdict, and .vpncheck returns the classification on its own. Three sources are layered, and a positive flag from any of them survives the merge:

LayerWhat it contributesKey
ipquery.ioRisk model: VPN, proxy, Tor, datacenter, mobile plus an aggregate score.none
ip-api.comIndependent proxy and hosting classification, used as a cross-check.none
ipapi.isVPN provider attribution and abuser history.IPAPI_IS_KEY

Cloud and DNS ranges are reported as hosting, never as a proxy: a datacenter address is normal for crawlers and cloud hosts, so it is not treated as evidence of evasion. Private and reserved space is labelled as such instead of being classified. Results are cached for thirty minutes.

Reading the verdict.vpncheck 1.1.1.1 returns the classification, confidence, per-flag signals, owning network, risk model and an exposure score, rendered as a Components V2 verdict card with source buttons. A clean verdict means nothing was flagged by these sources, not that the visitor is a real person.

Limits & caching

  • Eight slash lookups per ten seconds per user by default (the category wrappers share this bucket); the access console can raise or lower the ceiling and the window together.
  • Eight simultaneous watches by default, configurable up to 25; the watchtower refuses politely instead of dropping the oldest.
  • Network results are cached for CACHE_TTL seconds; invite resolution uses its own 30-second cache.
  • Report pages are bounded, so a large result never trips Discord's component ceiling.

Responsible use

Hard rulesThe instance is for defensive research on public data. It will not fetch breach dumps, access private accounts, guess credentials or help harass anyone. Phishing commands score lookalikes; they never register a domain or send a message.
  • Look up what you have a reason to look up, and keep the audit feed on.
  • Respect each source's terms and rate limits; the caches exist for that reason.
  • Handle availability and vanity claims manually. Automation breaks Discord's terms and usually the target server's too.
  • Approvals are per Discord ID. Review the list when someone leaves the team.
  • You are the operator: the audit rows are yours to answer for.
